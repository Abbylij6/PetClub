
# Guía de contribución – Pet Club

¡Bienvenido al desarrollo de Pet Club!

Este documento establece las reglas para colaborar en el proyecto.

## 1. Antes de comenzar

- Leer el README.md.
- Consultar la documentación de la carpeta docs.
- Revisar las tareas pendientes.
- Actualizar la rama develop antes de comenzar.

## 2. Flujo de trabajo

1. Actualizar develop.
2. Crear una rama para cada tarea.
3. Realizar los cambios correspondientes.
4. Probar el trabajo realizado.
5. Crear un commit descriptivo.
6. Subir la rama a GitHub.
7. Crear un Pull Request hacia develop.
8. Revisar los cambios.
9. Integrar el Pull Request.

## 3. Reglas generales

- No trabajar directamente en main.
- No trabajar directamente en develop.
- No subir contraseñas ni claves privadas.
- No utilizar git push --force.
- Mantener los cambios organizados.
- Documentar las decisiones importantes.

## 4. Convenciones de ramas

- feature/: funcionalidades nuevas.
- fix/: correcciones de errores.
- docs/: documentación.
- design/: cambios de diseño.
- refactor/: mejoras de código.
- chore/: mantenimiento.

## 5. Convenciones de commits

- feat: nueva funcionalidad.
- fix: corrección de errores.
- docs: documentación.
- design: cambios visuales.
- refactor: reorganización de código.
- test: pruebas.
- chore: mantenimiento.

## 6. Pull Requests

Todo cambio debe proponerse mediante un Pull Request.

La rama de destino habitual es develop.

La rama main contiene las versiones estables del proyecto.
